## Wann man es verwendet

`/impeccable audit` ist das technische Gegenstück zu `/impeccable critique`. Wo `/impeccable critique` fragt „fühlt sich das richtig an", fragt `/impeccable audit` „hält das stand". Es führt Barrierefreiheits-, Performance-, Theming-, Responsive-Design- und Anti-Pattern-Prüfungen an der Implementierung durch, bewertet jede Dimension von 0 bis 4 und erstellt einen Plan mit P0- bis P3-Schweregraden.

Verwenden Sie es vor dem Launch, während eines Quality Sprints oder wann immer ein Tech Lead sagt „wir sollten uns wirklich Barrierefreiheit ansehen".

## Wie es funktioniert

Der Skill scannt Ihren Code über fünf Dimensionen:

1. **Barrierefreiheit**: WCAG-Kontrast, ARIA, Tastaturnavigation, semantisches HTML, Formular-Labels.
2. **Performance**: Layout-Thrashing, teure Animationen, fehlendes Lazy Loading, Bundle-Größe.
3. **Theming**: hartkodierte Farben, Dark-Mode-Abdeckung, Token-Konsistenz.
4. **Responsive**: Breakpoint-Verhalten, Touch-Ziele, Mobile-Viewport-Handhabung.
5. **Anti-Patterns**: dieselben deterministischen 25 Prüfungen, die der Detektor ausführt.

Jede Dimension erhält eine 0-bis-4-Bewertung. Jeder Befund erhält einen Schweregrad: P0 blockiert den Release, P1 sollte in diesem Sprint behoben werden, P2 ist der nächste Zyklus, P3 ist Feinschliff. Sie erhalten ein einzelnes Dokument zurück, das Sie in einen Ticket-Tracker einfügen können.

Audit repariert nichts. Es dokumentiert. Leiten Sie die Befunde an `/impeccable polish`, `/impeccable harden` oder `/impeccable optimize` weiter, je nach Kategorie.

## Ausprobieren

```
/impeccable audit the checkout flow
```

Erwartete Ausgabe:

```
Barrierefreiheit: 2/4 (teilweise)
  P0: Fehlende Formular-Labels bei 4 Eingabefeldern
  P1: Kontrast 3,1:1 beim deaktivierten Button-Zustand
  P2: Kein sichtbarer Fokus-Indikator am benutzerdefinierten Dropdown

Performance: 3/4 (gut)
  P1: Hero-Bild nicht lazy-loaded (340KB)
  ...
```

Übergeben Sie die P0s an `/impeccable harden`, die Theming- und Typografie-P1s an `/impeccable typeset` und `/impeccable polish`, den Rest an `/impeccable polish`.

## Fallstricke

- **Verwechslung mit `/impeccable critique`.** Audit ist Implementierungsqualität. Critique ist Designqualität. Führen Sie beide für ein vollständiges Bild aus.
- **P3s vor P0s beheben.** Die Schweregrad-Skala existiert aus einem Grund. Beginnen Sie oben.
- **Die Dimensionen überspringen, von denen Sie denken, dass sie in Ordnung sind.** Theming und Responsive sind diejenigen, von denen die meisten Leute annehmen, sie seien in Ordnung, bis sie es nicht sind.
