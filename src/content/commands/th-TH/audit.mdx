## เมื่อไรควรใช้

`/impeccable audit` คือคู่เทียบเท่าทางเทคนิคของ `/impeccable critique` ในขณะที่ `/impeccable critique` ถามว่า "นี่รู้สึกถูกต้องไหม" `/impeccable audit` ถามว่า "นี่ทนได้ไหม" มันรันการตรวจสอบการเข้าถึง ประสิทธิภาพ ธีม การออกแบบเรสปอนซิฟ และแอนตี้แพทเทิร์นกับการสร้าง ให้คะแนนแต่ละมิติ 0 ถึง 4 และสร้างแผนพร้อมระดับความรุนแรง P0 ถึง P3

ใช้ก่อนส่งมอบ ระหว่างสปริ้นท์คุณภาพ หรือเมื่อใดก็ตามที่เทคลีดพูดว่า "เราควรดูเรื่องการเข้าถึงจริงๆ"

## วิธีการทำงาน

สกิลสแกนโค้ดของคุณในห้ามิติ:

1. **การเข้าถึง**: คอนทราสต์ WCAG, ARIA, การนำทางคีย์บอร์ด, HTML แบบเซแมนติก, เลเบิลฟอร์ม
2. **ประสิทธิภาพ**: การกระตุกเลย์เอาต์ แอนิเมชันที่หนัก การขาดการโหลดแบบ lazy น้ำหนักบันเดิล
3. **ธีม**: สีที่ฮาร์ดโค้ด ความครอบคลุมโหมดมืด ความสม่ำเสมอของโทเคน
4. **เรสปอนซิฟ**: พฤติกรรมเบรกพอยต์ เป้าหมายสัมผัส การจัดการวิวพอร์ตมือถือ
5. **แอนตี้แพทเทิร์น**: การตรวจสอบแบบกำหนดได้ 25 รายการเหมือนที่ตัวตรวจจับรัน

แต่ละมิติได้คะแนน 0 ถึง 4 แต่ละข้อค้นพบได้ระดับความรุนแรง: P0 บล็อก release, P1 ควรแก้สปริ้นท์นี้, P2 คือรอบถัดไป, P3 คือการปรับแต่ง คุณได้เอกสารเดียวที่วางลงในตัวติดตามติเก็ตได้

Audit ไม่ได้แก้ไขอะไรเลย มันบันทึกเอกสาร ส่งต่อข้อค้นพบไปที่ `/impeccable polish`, `/impeccable harden` หรือ `/impeccable optimize` ขึ้นอยู่กับหมวดหมู่

## ลองใช้งาน

```
/impeccable audit the checkout flow
```

ผลลัพธ์ที่คาดหวัง:

```
Accessibility: 2/4 (partial)
  P0: Missing form labels on 4 inputs
  P1: Contrast 3.1:1 on disabled button state
  P2: No visible focus indicator on custom dropdown

Performance: 3/4 (good)
  P1: Hero image not lazy-loaded (340KB)
  ...
```

ส่ง P0 ให้ `/impeccable harden` ธีมและตัวอักษร P1 ให้ `/impeccable typeset` และ `/impeccable polish` ที่เหลือให้ `/impeccable polish`

## ข้อควรระวัง

- **สับสนกับ `/impeccable critique`** Audit คือคุณภาพการสร้าง Critique คือคุณภาพการออกแบบ รันทั้งสองอย่างเพื่อภาพรวมที่สมบูรณ์
- **แก้ P3 ก่อน P0** สเกลระดับความรุนแรงมีอยู่ด้วยเหตุผล เริ่มจากด้านบน
- **ข้ามมิติที่คุณคิดว่าใช้ได้** ธีมและเรสปอนซิฟคือสิ่งที่คนส่วนใหญ่คิดว่าใช้ได้จนกระทั่งพวกมันไม่ได้
