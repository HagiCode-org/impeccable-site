## เมื่อไรควรใช้

`/impeccable craft` คือคำสั่งสร้างแบบครบวงจร ให้คำอธิบายฟีเจอร์แล้วมันจะรันไปป์ไลน์ทั้งหมด: การค้นหาข้อมูลแบบมีโครงสร้าง การโหลดอ้างอิง การสร้าง การวนซ้ำภาพ ใช้เมื่อคุณเริ่มฟีเจอร์ใหม่จากศูนย์และต้องการเวิร์กโฟลว์ทั้งหมดในการเรียกครั้งเดียว

ใช้เมื่อ:

- **คุณกำลังสร้างฟีเจอร์ใหม่และต้องการโฟลว์แบบเต็ม** คุณไม่ต้องการจัดการขั้นตอนด้วยตัวเอง
- **คุณรู้ว่ากำลังสร้างอะไรแต่ไม่รู้ว่ามันควรมีหน้าตาอย่างไร** เฟสค้นพบบังคับให้คิดเรื่องการออกแบบก่อนที่การสร้างจะล็อคมันไว้
- **คุณต้องการการวนซ้ำภาพโดยค่าดีฟอลต์** `craft` ตรวจสอบผลลัพธ์ในเบราว์เซอร์และปรับแต่งจนกว่าคุณภาพจะสูง แทนที่จะส่งเวอร์ชันทำงานได้เวอร์ชันแรก

หากคุณต้องการแค่การคิดโดยไม่มีโค้ด ใช้ `/impeccable shape` แบบสแตนด์อโลน หากคุณมีวิชันชัดเจนแล้วและต้องการแค่สร้าง เรียก `/impeccable` โดยตรงพร้อมคำอธิบายฟีเจอร์ของคุณ `craft` อยู่ตรงกลาง: มีโครงสร้าง ครบถ้วน มีความเห็นชัดเจน

## วิธีการทำงาน

`craft` รันสี่เฟสตามลำดับ:

1. **กำหนดรูปแบบการออกแบบ** รัน `/impeccable shape` ภายใน: การสนทนาค้นพบสั้นๆ เกี่ยวกับวัตถุประสงค์ ผู้ใช้ เนื้อหา ข้อจำกัด และเป้าหมาย ผลลัพธ์คือบรีฟการออกแบบที่คุณอ่านและค้านได้
2. **โหลดอ้างอิง** จากบรีฟ ดึงไฟล์อ้างอิงที่เหมาะสม (ปริภูมิ ตัวอักษร การเคลื่อนไหว สี การโต้ตอบ เรสปอนซิฟ การเขียน UX) เพื่อให้โมเดลมีหลักการที่เกี่ยวข้องโหลดก่อนเริ่มเขียนโค้ด
3. **สร้าง** สร้างฟีเจอร์ตามลำดับที่รอบคอบ: โครงสร้างก่อน แล้วระยะห่างและลำดับชั้น แล้วตัวอักษรและสี แล้วสเตท แล้วการเคลื่อนไหว แล้วเรสปอนซิฟ ทุกการตัดสินใจสืบย้อนไปถึงบรีฟ
4. **วนซ้ำภาพ** เปิดผลลัพธ์ในเบราว์เซอร์ ตรวจสอบกับบรีฟและแคตตาล็อกแอนตี้แพทเทิร์น และปรับแต่งจนกว่าจะตรงกับเจตนา ขั้นตอนนี้สำคัญมาก เวอร์ชันทำงานได้เวอร์ชันแรกไม่ใช่เวอร์ชันที่ส่งมอบ

เฟสค้นพบไม่สามารถข้ามได้และนั่นคือประเด็น UI ที่สร้างจาก AI ส่วนใหญ่ล้มเหลวเพราะไม่มีใครถามว่าผู้ใช้พยายามทำอะไรก่อนที่โมเดลจะเริ่มเขียน JSX `craft` กลับด้านสิ่งนั้น

## ลองใช้งาน

```
/impeccable craft a pricing page for a developer tool
```

คาดหวังการสัมภาษณ์ค้นหาข้อมูล 5-10 คำถามก่อน คำถามเกี่ยวกับกลุ่มผู้ชมของคุณ บุคลิกของผลิตภัณฑ์ โทนอารมณ์ที่คุณต้องการ การอ้างอิงตรงข้าม และข้อจำกัด แล้วตามด้วยบรีฟการออกแบบ แล้วการสร้าง โดยตรวจสอบในเบราว์เซอร์ทุกขั้นตอน คาดหวังหลายรอบของการวนซ้ำในเฟสปรับแต่งภาพ

การรันทั้งหมดนานกว่าคำสั่งทั่วไปเพราะรวมการคิด การสร้าง และการปรับแต่ง นั่นคือการแลกเปลี่ยน: โครงสร้างล่วงหน้ามากขึ้น การแก้ไขทีหลังน้อยลง

## ข้อควรระวัง

- **ใช้สำหรับการเปลี่ยนแปลงเล็กน้อย** `craft` มีไว้สำหรับฟีเจอร์ใหม่ ไม่ใช่การแตะแต้ง สำหรับโค้ดที่มีอยู่ ใช้ `/impeccable polish`, `/impeccable critique` หรือคำสั่งปรับปรุงเฉพาะทางแทน
- **รีบร้อนในเฟสค้นพบ** การสัมภาษณ์รู้สึกช้าเมื่อเทียบกับ "แค่เริ่มเขียนโค้ด" แต่ไม่ใช่ การตอบคำถามอย่างรอบคอบให้บรีฟที่คมชัดกว่า ซึ่งให้ผลสร้างที่คมชัดกว่า ซึ่งให้การเขียนใหม่น้อยลง
- **ข้ามการวนซ้ำภาพ** เฟสนี้มีอยู่ด้วยเหตุผล ช่องว่างระหว่าง "ทำงานได้ทางเทคนิค" และ "รู้สึกถูกต้อง" ถูกปิดด้วยการปรับแต่งภาพ ไม่ใช่การรีวิวโค้ด ปล่อยให้มันรัน
