## เมื่อไรควรใช้

`/impeccable` คือคำสั่งหลัก เรียกใช้โดยตรงเมื่อคุณต้องการงานออกแบบแบบอิสระโดยโหลดคู่มือออกแบบทั้งหมด โดยไม่ต้องเลือกคำสั่งเฉพาะทาง เป็นทางเลือกสำรองเมื่อคำสั่งเฉพาะทาง 23 คำสั่ง (`audit`, `polish`, `critique` และอื่นๆ) ไม่ตรงกับสิ่งที่คุณกำลังทำ

ใช้ `/impeccable` โดยตรงเมื่อ:

- **คุณไม่แน่ใจว่าคำสั่งไหนเหมาะสม** อธิบายสิ่งที่คุณต้องการเป็นภาษาธรรมดาแล้วให้สกิลเลือกแนวทางที่เหมาะสม
- **งานครอบคลุมหลายสาขา** "ทำ hero section ใหม่" กระทบเลย์เอาต์ ตัวอักษร สี และการเคลื่อนไหว คำสั่งเดียวไม่สามารถครอบครองทั้งหมดได้
- **คุณต้องการระบบอัจฉริยะด้านการออกแบบแบบเต็มรูปแบบโดยไม่มีข้อจำกัด** โหลดไฟล์อ้างอิงทุกไฟล์ ตรวจสอบแอนตี้แพทเทิร์นทุกข้อ ไม่มีเวิร์กโฟลว์ที่ตั้งไว้ล่วงหน้า

สำหรับโฟลว์ที่มีโครงสร้าง ใช้คำสั่งเฉพาะทางในแถบด้านข้าง รัน `/impeccable teach` ก่อนในทุกโปรเจกต์ใหม่เพื่อสร้าง PRODUCT.md และ DESIGN.md `/impeccable craft` เชื่อมการสัมภาษณ์ค้นหาข้อมูลเข้ากับการสร้างงานแบบเต็มรูปแบบพร้อมการวนซ้ำภาพแบบเรียลไทม์ `/impeccable shape` สร้างบรีฟการออกแบบโดยไม่ต้องแตะโค้ด `/impeccable live` ให้ตัวเลือกเบราว์เซอร์พร้อมตัวเลือกสามแบบต่ออิลิเมนต์ คำสั่งประเมินและปรับปรุง (`audit`, `critique`, `polish`, `typeset`, `layout`, `colorize` และอื่นๆ) แต่ละคำสั่งดูแลส่วนงานเฉพาะของตัวเอง

## วิธีการทำงาน

UI ที่สร้างจาก AI ส่วนใหญ่ล้มเหลวในลักษณะเดียวกัน: ฟอนต์ทั่วไป ไล่สีม่วง การ์ดกริดซ้อนการ์ดกริด กระจกเงาทุกที่ `/impeccable` ให้จุดยืนที่แข็งแกร่งแก่ AI ของคุณ โหลดคู่มือออกแบบที่มีความเห็นชัดเจน บวกกับรายการแอนตี้แพทเทิร์นยาวๆ แล้วผลักดันโมเดลให้ยึดมั่นในทิศทางสุนทรียะเฉพาะเจาะจงก่อนเขียนโค้ดแม้แต่บรรทัดเดียว

ไฟล์สองไฟล์ที่รูทโปรเจกต์ของคุณกำหนดทุกสิ่งที่สกิลทำ:

- **`PRODUCT.md`** มีระดับภาษา (แบรนด์ vs ผลิตภัณฑ์) ผู้ใช้เป้าหมาย บุคลิกแบรนด์ การอ้างอิงตรงข้าม หลักการออกแบบ ตอบคำถาม "ใคร อะไร ทำไม"
- **`DESIGN.md`** มีสี ตัวอักษร ระดับความสูง คอมโพเนนต์ สิ่งที่ควรและไม่ควรทำ ในรูปแบบ Google Stitch หกส่วน ตอบคำถาม "หน้าตาเป็นอย่างไร"

ทุกคำสั่งอ่านทั้งสองไฟล์ก่อนสร้างผลลัพธ์ **ระดับภาษา** กำหนดค่าดีฟอลต์ที่โหลด แบรนด์ (การตลาด, แลนดิง, พอร์ตโฟลิโอ, ที่การออกแบบคือตัวผลิตภัณฑ์) และผลิตภัณฑ์ (UI แอป, แดชบอร์ด, เครื่องมือ, ที่การออกแบบรับใช้ผลิตภัณฑ์) มีค่าดีฟอลต์ต่างกันสำหรับตัวอักษร การเคลื่อนไหว สี และความหนาแน่น การระบุเพียงครั้งเดียวใน PRODUCT.md หมายความว่า `/impeccable typeset` จะไม่ดันฟอนต์นิตยสารบรรณาธิการใส่แดชบอร์ด และจะไม่ดันค่าดีฟอลต์สำหรับผลิตภัณฑ์ใส่หน้าแคมเปญ ดู [บทช่วยสอนแบรนด์ vs ผลิตภัณฑ์](/tutorials/brand-vs-product) สำหรับความแตกต่างระหว่างทั้งสองแบบ

ในการใช้งานครั้งแรกในโปรเจกต์ สกิลจะรันโฟลว์ `teach` อัตโนมัติ: การสัมภาษณ์สั้นๆ ที่เขียน PRODUCT.md แล้วมอบหมายให้ `/impeccable document` สร้าง DESIGN.md คำสั่งถัดไปจะอ่านไฟล์โดยไม่ต้องถามอีก

## ลองใช้งาน

```
/impeccable redo this hero section
```

```
/impeccable build me a pricing page for a developer tool
```

ทั้งสองพรอมต์จงใจให้คลุมเครือ `/impeccable` จะเลือกทิศทางสุนทรียะที่แข็งแกร่งสอดคล้องกับระดับภาษาของคุณ ยึดมั่นในฟอนต์ที่ไม่ใช่ค่าดีฟอลต์ หลีกเลี่ยงพาเลตสี AI และทำการเลือกแบบเฉพาะเจาะจงในแบบที่นักออกแบบจะทำ ไม่ต้องเลือกชื่อคำสั่งก่อน ไม่ต้องทำตามเวิร์กโฟลว์ทีละขั้นตอน

สำหรับการวนซ้ำภาพในเบราว์เซอร์แทนการแชท:

```
/impeccable live
```

เลือกอิลิเมนต์ใดก็ได้บนเดฟเซิร์ฟเวอร์ที่กำลังรัน วางความคิดเห็นหรือเส้นขอบ รับตัวเลือกสามแบบคุณภาพระดับการผลิตสลับเข้ามาผ่าน HMR เลือกตัวที่คุณต้องการแล้วมันจะเขียนกลับไปยังซอร์ส

## ปักหมุดคำสั่งเป็นทางลัด

เวอร์ชัน 3.0 รวมสกิลแบบสแตนด์อโลน 18 อันเข้าเป็น `/impeccable` เดียวพร้อมคำสั่งย่อย 23 คำสั่ง หากคุณคิดถึงรูปแบบสั้นของคำสั่งเฉพาะเจาะจง ปักหมุดกลับมาได้:

```
/impeccable pin critique
```

จากนี้ไป `/critique` จะเรียก `/impeccable critique` โดยตรง มันเขียนสกิลเรียกซ้ำแบบเบาที่มอบหมายให้พาเรนต์ ดังนั้นการอัปเดตสกิลจะไหลผ่านโดยไม่ต้องปักหมุดใหม่

ทางลัดที่น่าลอง:

- `/impeccable pin polish` สำหรับงานผ่านขั้นสุดท้าย
- `/impeccable pin audit` สำหรับการตรวจสอบ a11y/performance แบบกำหนดได้
- `/impeccable pin live` สำหรับโฟลว์วนซ้ำในเบราว์เซอร์
- `/impeccable pin critique` สำหรับรีวิวการออกแบบ

หากต้องการลบ: `/impeccable unpin critique` ทางลัดอยู่ในรูปโฟลเดอร์ที่ขึ้นต้นด้วย `i-` ในโฟลเดอร์สกิลของคุณ (`.claude/skills/i-critique/`, `.cursor/skills/i-critique/` ฯลฯ) คุณสามารถลบด้วยตนเองได้เช่นกัน

## ข้อควรระวัง

- **ถือว่าเป็นคู่มือสไตล์** นี่เป็นพาร์ทเนอร์ออกแบบที่มีความเห็นชัดเจน ไม่ใช่ตัวตรวจสอบโค้ด ค่าดีฟอลต์มีอยู่เพื่อยกระดับพื้นฐาน ไม่ใช่เพื่อแทนที่การตัดสินใจของคุณ หากคุณมีเหตุผลที่แท้จริงในการค้าน (แนวทางแบรนด์ ข้อจำกัดการเข้าถึง การวิจัยผู้ใช้) ค้านและอธิบายว่าทำไม สกิลจะทำงานร่วมกับคุณ สิ่งที่ทำให้ผลลัพธ์แย่ลงคือการเพิกเฉอความคิดเห็นโดยไม่มีเหตุผล
- **คาดหวังให้มันแก้ไขโค้ดที่มีอยู่** `/impeccable` มีไว้สำหรับการสร้าง สำหรับการปรับปรุง ใช้ `/impeccable polish`, `/impeccable distill` หรือ `/impeccable critique` แทน
- **รันก่อนที่ `teach` จะมีโอกาสบันทึกบริบท** ในโปรเจกต์ใหม่มันจะสัมภาษณ์คุณระหว่างทำงาน ซึ่งใช้ได้แต่ช้ากว่า การรัน `/impeccable teach` อย่างชัดเจนเป็นคำสั่งแรกของคุณจะราบรื่นกว่าเล็กน้อย
- **ข้ามคำถามระดับภาษา** ค่าดีฟอลต์ของแบรนด์และผลิตภัณฑ์แตกต่างกันพอที่การรันด้วยระดับภาษาผิดจะให้ผลลัพธ์ที่คลาดเคลื่อนเล็กน้อย หาก `PRODUCT.md` ไม่มีฟิลด์ `## Register` (เก่า) ให้รัน `/impeccable teach` เพื่อเพิ่ม
