## เมื่อไรควรใช้

`/impeccable polish` คือสิ่งสุดท้ายที่คุณรันก่อนส่งมอบ มันตามล่ารายละเอียดเล็กๆ ที่แยกฟีเจอร์ที่ส่งมอบออกจากฟีเจอร์ที่ปรับแต่งแล้ว: การจัดเรียงผิดครึ่งพิกเซล ระยะห่างไม่สม่ำเสมอ สถานะโฟกัสที่ถูกลืม การเปลี่ยนโหลดที่กระพริบ ข้อความที่เบี่ยงเบนโทน มันยังจัดเรียงฟีเจอร์ให้สอดคล้องกับระบบการออกแบบของคุณ แทนที่ค่าที่ฮาร์ดโค้ดด้วยโทเคน สลับคอมโพเนนต์ที่กำหนดเองเป็นส่วนที่ใช้ร่วมกัน และแก้ไขการเบี่ยงเบนจากรูปแบบที่กำหนดไว้

ใช้เมื่อฟีเจอร์ทำงานได้สมบูรณ์ทางฟังก์ชัน ไม่มีอะไรเสีย และบางอย่างยังรู้สึกแปลก ใช้เมื่อฟีเจอร์ได้เบี่ยงเบนจากระบบการออกแบบและต้องการดึงกลับเข้าที่

## วิธีการทำงาน

Polish เริ่มจากการค้นพบระบบการออกแบบ (โทเคน สเกลระยะห่าง คอมโพเนนต์ที่ใช้ร่วมกัน) แล้วทำงานอย่างเป็นระบบในหกมิติ:

1. **การจัดเรียงภาพและระยะห่าง**: การยึดกริดแบบ pixel-perfect สเกลระยะห่างที่สม่ำเสมอ การจัดเรียงออปติคัลบนไอคอน
2. **ตัวอักษร**: ความสม่ำเสมอของลำดับชั้น ความยาวบรรทัด วิดาวและออร์แฟน เคอร์นิงบนหัวข้อ
3. **สีและคอนทราสต์**: การใช้โทเคน ความเท่าเทียมของธีม อัตราส่วน WCAG ตัวบ่งชี้โฟกัส
4. **สถานะการโต้ตอบ**: hover, focus, active, disabled, loading, error, success ทุกสถานะได้รับการดูแล
5. **การเปลี่ยนและการเคลื่อนไหว**: อีซิ่งที่นุ่มนวล ไม่มีอาการกระตุกของเลย์เอาต์ เคารพ `prefers-reduced-motion`
6. **ข้อความ**: เสียงที่สม่ำเสมอ กาลเวลาที่ถูกต้อง ไม่มีสตริงตัวอย่าง ไม่มี TODO ที่หลงเหลือ

สกิลชัดเจนเรื่องหนึ่ง: polish เป็นขั้นตอนสุดท้าย ไม่ใช่ขั้นตอนแรก หากฟีเจอร์ยังไม่เสร็จสมบูรณ์ทางฟังก์ชัน การ polish มันคืองานที่สูญเปล่า

## ลองใช้งาน

```
/impeccable polish the pricing page
```

การรันที่ดีมีลักษณะเช่นนี้:

```
Visual alignment: fixed 3 off-grid elements (8px baseline)
Typography: tightened h1 kerning, fixed widow on testimonial
Interaction: added hover state on FAQ items, focus ring on email input
Motion: softened modal entrance, added reduced-motion fallback
Copy: removed one "Lorem ipsum" stray, aligned button voice
```

ห้าการแก้ไขเล็กน้อย ไม่มีการเขียนใหม่ นี่คือรูปร่างของพาส polish ที่ดี

## ข้อควรระวัง

- **Polish งานที่ยังไม่เสร็จ** หากมี TODO ในโค้ด คุณยังไม่พร้อม รัน `/impeccable polish` บนฟีเจอร์ที่เสร็จแล้วเท่านั้น
- **ถือว่า polish เป็นการออกแบบใหม่** Polish ปรับแต่งสิ่งที่มีอยู่ หากคุณพบว่ากำลังสร้างเลย์เอาต์ใหม่ คุณต้องการ `/impeccable critique` หรือ `/impeccable layout` แทน
- **รัน `/impeccable polish` โดยไม่มี `/impeccable audit` ก่อน** Polish จับปัญหาแบบรู้สึก Audit จับปัญหาแบบวัดได้ ใช้ทั้งสองอย่าง
