## 사용 시기

`/impeccable clarify`는 사람들을 멈추고 생각하게 만드는 인터페이스 텍스트를 위한 것입니다. 혼란스러운 레이블, 모호한 버튼 카피, 사용자를 탓하는 에러 메시지, 레이블을 반복하는 툴팁, 쓸모없는 말을 하는 빈 상태. 문제가 레이아웃이나 색상이 아닌 단어일 때 사용하세요.

좋은 트리거: "사용자가 이 필드를 이해하지 못해요", "에러 메시지가 도움이 되지 않아요", "좋은 버튼 카피를 쓸 수 없어요", "이 툴팁은 낭비예요".

## 작동 방식

스킬은 대부분의 UX 카피 문제가 있는 표면에서 텍스트를 다시 씁니다:

1. **레이블과 필드 힌트**: 직접적, 구체적, 기대하는 것을 말함.
2. **버튼 카피**: 동사 우선, 액션이 아닌 결과를 설명. "OK"가 아닌 "변경 사항 저장".
3. **에러 메시지**: 무엇이 잘못되었는지, 누구의 잘못인지, 다음에 무엇을 해야 하는지 설명. 절대 사용자를 탓하지 않음.
4. **빈 상태**: 사용자를 안내하고, 상태가 비어 있는 이유를 설명하고, 다음 단계를 제공.
5. **툴팁과 도움말 텍스트**: 레이블이 담을 수 없는 정보를 추가, 절대 반복하지 않음.
6. **확인 대화상자**: 액션이 아닌 결과를 명명.

스킬은 `PRODUCT.md`의 대상 사용자와 심리 상태를 사용하여 목소리를 조율합니다. 기술적 대상에게는 정확한 언어. 소비자 대상에게는 평이한 말투. 바쁜 사용자에게는 짧은 텍스트. 불안한 사용자(결제, 삭제)에게는 안심.

## 직접 해보기

```
/impeccable clarify the billing form
```

이전과 이후, 일반적:

- 레이블 "Billing address" → "카드에 적힌 주소"
- 플레이스홀더 "Enter your VAT ID" → "VAT ID (선택, 비즈니스용)"
- 에러 "Invalid input" → "이 카드 번호는 15자리입니다. 14자리를 입력했습니다."
- 버튼 "Submit" → "$29 결제 및 구독"
- 빈 상태 "No transactions yet" → "첫 주문 후 첫 결제가 여기에 표시됩니다."

## 주의 사항

- **더 명확하게가 아닌 더 영리하게 쓰기.** Clarify는 목소리 업그레이드용이 아닙니다. 카피가 이미 명확하다면 이 스킬을 사용하지 마세요. 개성을 원할 때 `/impeccable delight`를 대신 사용하세요.
- **대상 질문 건너뛰기.** Clarify는 누가 읽는지 알아야 합니다. `PRODUCT.md`에 대상 기술 수준이 지정되어 있지 않으면 다시 쓰기가 일반적일 것입니다.
- **마케팅 카피에 clarify 실행하기.** Clarify는 기능적 UX 텍스트용입니다: 레이블, 에러, 지시. 마케팅 카피는 다른 접근과 인간 작성자가 필요합니다.
