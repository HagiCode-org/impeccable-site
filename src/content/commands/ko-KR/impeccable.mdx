## 사용 시기

`/impeccable`은 홈 명령입니다. 전문 명령을 고르지 않고, 전체 가이드북이 로드된 상태로 자유로운 형태의 디자인 작업을 원할 때 직접 호출하세요. 23개의 전문 명령(`audit`, `polish`, `critique` 등)이 하려는 작업에 정확히 매핑되지 않을 때 찾게 되는 기본 선택지입니다.

다음 경우에 `/impeccable`을 직접 사용하세요:

- **어떤 명령이 맞는지 확실하지 않을 때.** 원하는 것을 자연어로 설명하면 스킬이 알맞은 접근 방식을 선택합니다.
- **작업이 여러 영역에 걸쳐 있을 때.** "히어로 섹션을 다시 만들어줘"는 레이아웃, 타이포, 색상, 모션을 모두 건드립니다. 하나의 명령으로는 감당할 수 없습니다.
- **제약 없는 전체 디자인 인텔리전스를 원할 때.** 모든 레퍼런스 파일이 로드되고, 모든 안티패턴이 검사되며, 미리 정해진 워크플로가 없습니다.

구조화된 흐름을 원하면 사이드바의 전문 명령을 사용하세요. 새 프로젝트에서는 먼저 `/impeccable teach`를 실행하여 PRODUCT.md와 DESIGN.md를 만드세요. `/impeccable craft`는 디스커버리 인터뷰를 전체 빌드와 실시간 시각 반복으로 이어줍니다. `/impeccable shape`은 코드를 건드리지 않고 디자인 브리프만 만듭니다. `/impeccable live`는 요소별로 세 가지 변형을 보여주는 브라우저 픽커를 제공합니다. 평가 및 정제 명령(`audit`, `critique`, `polish`, `typeset`, `layout`, `colorize` 등)은 각각 작업의 특정 영역을 담당합니다.

## 작동 방식

대부분의 AI 생성 UI는 같은 방식으로 실패합니다: 평범한 폰트, 보라색 그라데이션, 카드 위에 카드, 어디에나 글래스모피즘. `/impeccable`은 AI에 강한 관점을 부여합니다. 주관적인 디자인 핸드북과 긴 안티패턴 목록을 로드한 뒤, 한 줄의 코드도 작성하기 전에 특정 미적 방향에 커밋하도록 모델을 유도합니다.

프로젝트 루트의 두 파일이 스킬의 모든 동작을 결정합니다:

- **`PRODUCT.md`**는 레지스터(brand vs product), 대상 사용자, 브랜드 성격, 안티 레퍼런스, 디자인 원칙을 담습니다. "누가, 무엇을, 왜"에 대답합니다.
- **`DESIGN.md`**는 색상, 타이포그래피, 엘리베이션, 컴포넌트, 권장/비권장 사항을 6단계 Google Stitch 형식으로 담습니다. "어떻게 보이는가"에 대답합니다.

모든 명령은 생성 전 두 파일을 읽습니다. **레지스터**는 어떤 기본값이 로드되는지 결정합니다. Brand(마케팅, 랜딩, 포트폴리오, 디자인 자체가 제품인 경우)과 product(앱 UI, 대시보드, 도구, 디자인이 제품을 보조하는 경우)는 타이포, 모션, 색상, 밀도에서 서로 다른 기본값을 가집니다. PRODUCT.md에 한 번만 지정하면, `/impeccable typeset`이 대시보드에 에디토리얼 매거진 폰트를 추천하거나 캠페인 페이지에 product 기본 스타일을 적용하는 일이 없습니다. 두 레지스터가 어떻게 다른지는 [brand vs product 튜토리얼](/tutorials/brand-vs-product)을 참고하세요.

프로젝트에서 처음 사용하면 스킬이 자동으로 `teach` 흐름을 실행합니다: 짧은 인터뷰로 PRODUCT.md를 작성하고, 이어서 `/impeccable document`에 위임하여 DESIGN.md를 생성합니다. 이후 명령들은 다시 묻지 않고 파일을 읽습니다.

## 직접 해보기

```
/impeccable redo this hero section
```

```
/impeccable build me a pricing page for a developer tool
```

두 프롬프트 모두 의도적으로 모호합니다. `/impeccable`은 레지스터에 맞는 강한 미적 방향을 선택하고, 비기본 폰트에 커밋하며, AI 색상 팔레트를 피하고, 진짜 디자이너가 내릴 구체적인 결정들을 내립니다. 먼저 고를 명령도, 따라야 할 단계별 워크플로도 없습니다.

채팅 대신 브라우저에서 시각적으로 반복 작업을 원한다면:

```
/impeccable live
```

실행 중인 dev server에서 아무 요소나 선택하고, 코멘트를 남기거나 스트로크를 그리세요. 세 가지 프로덕션 품질의 변형이 HMR로 핫스왑됩니다. 원하는 것을 수락하면 소스에 바로 기록됩니다.

## 명령을 바로가기로 고정하기

v3.0은 18개의 독립 스킬을 23개의 하위 명령을 가진 단일 `/impeccable`로 통합했습니다. 특정 명령의 짧은 형태가 그리우면 다시 고정하세요:

```
/impeccable pin critique
```

이제부터 `/critique`가 `/impeccable critique`를 직접 호출합니다. 부모에 위임하는 가벼운 리다이렉트 스킬을 작성하므로, 스킬이 업데이트되어도 다시 고정할 필요가 없습니다.

유용한 고정 예시:

- `/impeccable pin polish` — 최종 마감 작업용
- `/impeccable pin audit` — 결정론적 a11y/퍼포먼스 검사용
- `/impeccable pin live` — 브라우저 반복 흐름용
- `/impeccable pin critique` — 디자인 리뷰용

해제: `/impeccable unpin critique`. 고정은 harness 스킬 폴더(`.claude/skills/i-critique/`, `.cursor/skills/i-critique/` 등)에 `i-` 접두사 디렉터리로 존재하므로 수동으로 삭제할 수도 있습니다.

## 주의 사항

- **스타일 가이드처럼 취급하기.** 이것은 주관적인 디자인 파트너이지 린터가 아닙니다. 기본값은 하한선을 높이기 위해 존재하며, 여러분의 판단을 대체하기 위한 것이 아닙니다. 반대할 타당한 이유(브랜드 가이드라인, 접근성 제약, 사용자 연구)가 있다면 이유를 설명하며 밀어붙이세요. 스킬이 함께 작업할 것입니다. 이유 없이 관점을 무시하는 것이 더 나쁜 결과를 만듭니다.
- **기존 코드 수정을 기대하기.** `/impeccable`은 생성에 치중합니다. 정제 작업에는 `/impeccable polish`, `/impeccable distill`, 또는 `/impeccable critique`를 대신 사용하세요.
- **`teach`가 컨텍스트를 저장하기 전에 실행하기.** 새 프로젝트에서는 작업 중에 인터뷰를 진행하므로 작동은 하지만 더 느립니다. 첫 번째 명령으로 명시적으로 `/impeccable teach`를 실행하는 것이 조금 더 매끄럽습니다.
- **레지스터 건너뛰기.** Brand와 product의 기본값은 충분히 다르므로, 잘못된 레지스터에서 실행하면 미묘하게 어긋난 결과가 나옵니다. `PRODUCT.md`에 `## Register` 필드가 없다면(레거시), `/impeccable teach`를 다시 실행하여 추가하세요.
