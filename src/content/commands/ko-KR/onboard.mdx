## 사용 시기

`/impeccable onboard`은 새 사용자가 머무를지 결정하는 순간을 위한 것입니다: 첫 화면, 빈 상태, 설정 흐름, 제품 투어, "이제 뭘 하죠" 갭. 활성화가 약할 때, 새 사용자가 가치에 도달하기 전에 이탈할 때, 또는 빈 상태가 "아직 항목 없음"에서 멈출 때 사용하세요.

## 작동 방식

이 명령은 하나의 질문에서 시작합니다: aha 모멘트는 무엇이며, 새 사용자가 거기에 얼마나 빨리 도달할 수 있는가. 모든 디자인 결정은 그 순간을 향합니다.

첫인상을 형성하는 표면에서 작동합니다:

1. **첫 실행 경험**: 가입 직후의 순간들. 사용자가 투어, 빈 캔버스, 채워진 예시, 아무것도 없는 것 중 무엇을 봐야 하는지. 제품에 맞는 접근 방식 선택.
2. **빈 상태**: 모든 제로 데이터 화면이 안내됨. 여기는 어디인가, 왜 비어 있는가, 다음에 무엇을 해야 하는가, 채워지면 어떻게 보일 것인가.
3. **설치와 설정**: 필수 구성을 최소화, 스마트 기본값, 각 단계가 왜 중요한지 설명.
4. **점진적 공개**: 고급 기능은 자격을 얻을 때까지 길을 비켜섬.
5. **활성화 이벤트**: 사용자가 처음으로 핵심 가치를 경험하는 순간이 조용히 계측되고 축하됨.

이 명령은 두 가지 일반적 실패 모드에 저항합니다: 사용자가 아무것도 만질 수 없기 전에 캐러셀을 클릭하게 하는 과도한 튜토리얼 온보딩과, 사용자가 빈 앱에 떨어져 스스로 알아내야 하는 무온보딩.

## 직접 해보기

```
/impeccable onboard the editor
```

일반적 출력:

- 첫 실행: 빈 편집기를 사용자가 수정할 수 있는 채워진 예시 문서로 교체. 취소 버튼은 예시를 버리고, 편집은 사용자의 작업으로 내용을 대체.
- 문서 목록의 빈 상태: "아직 문서가 없습니다. 첫 문서를 만들거나 Notion, Google Docs, Markdown에서 가져오세요."
- 설정: 6개 필수 필드에서 1개(워크스페이스 이름)로 축소. 나머지는 스마트 기본값이 있고 나중에 설정에서 편집 가능.
- 활성화: 사용자가 처음으로 문서를 저장할 때 조용한 토스트가 "저장됨. 작업이 이제 클라우드에 있습니다."라고 말함. 일회성, 반복 없음.

## 주의 사항

- **기본 답으로 제품 투어 추가하기.** 대부분의 제품은 투어가 필요하지 않습니다. 더 나은 첫 화면이 필요합니다. 투어는 목발입니다.
- **aha 모멘트를 정의하지 않고 온보딩 설계하기.** 사용자가 첫 60초에 무엇을 느껴야 하는지 한 문장으로 말할 수 없다면 먼저 `/impeccable shape`로 돌아가세요.
- **부서진 흐름에 onboard 실행하기.** 먼저 흐름을 고치세요. 핵심 액션이 부서진 제품은 온보딩이 구할 수 없습니다.
