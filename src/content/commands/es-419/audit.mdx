## Cuando usarlo

`/impeccable audit` es la contraparte tecnica de `/impeccable critique`. Donde `/impeccable critique` pregunta "se siente bien", `/impeccable audit` pregunta "resiste el escrutinio". Ejecuta verificaciones de accesibilidad, rendimiento, temas, diseno responsive y anti-patrones contra la implementacion, puntua cada dimension de 0 a 4, y produce un plan con calificaciones de severidad P0 a P3.

Usalo antes de lanzar, durante un sprint de calidad, o cada vez que un lider tecnico dice "realmente deberiamos revisar la accesibilidad".

## Como funciona

La habilidad escanea tu codigo a traves de cinco dimensiones:

1. **Accesibilidad**: contraste WCAG, ARIA, navegacion por teclado, HTML semantico, etiquetas de formularios.
2. **Rendimiento**: thrashing de layout, animaciones costosas, lazy loading faltante, peso del bundle.
3. **Temas**: colores hardcodeados, cobertura de modo oscuro, consistencia de tokens.
4. **Responsive**: comportamiento en breakpoints, targets tactiles, manejo de viewport movil.
5. **Anti-patrones**: las mismas 25 verificaciones deterministas que ejecuta el detector.

Cada dimension recibe una puntuacion de 0 a 4. Cada hallazgo recibe una severidad: P0 bloquea el release, P1 deberia corregirse este sprint, P2 es el proximo ciclo, P3 es acabado. Recibes un unico documento que puedes pegar en un tracker de tickets.

Audit no corrige nada. Documenta. Enruta los hallazgos a `/impeccable polish`, `/impeccable harden` o `/impeccable optimize` segun la categoria.

## Probalo

```
/impeccable audit the checkout flow
```

Salida esperada:

```
Accessibility: 2/4 (partial)
  P0: Missing form labels on 4 inputs
  P1: Contrast 3.1:1 on disabled button state
  P2: No visible focus indicator on custom dropdown

Performance: 3/4 (good)
  P1: Hero image not lazy-loaded (340KB)
  ...
```

Entrega los P0 a `/impeccable harden`, los P1 de temas y tipografia a `/impeccable typeset` y `/impeccable polish`, el resto a `/impeccable polish`.

## Errores comunes

- **Confundirlo con `/impeccable critique`.** Audit es calidad de implementacion. Critique es calidad de diseno. Ejecuta ambos para una imagen completa.
- **Corregir P3s antes que P0s.** La escala de severidad existe por una razon. Empieza desde arriba.
- **Saltarse las dimensiones que crees que estan bien.** Temas y responsive son las que la mayoria asume que estan bien hasta que no lo estan.
