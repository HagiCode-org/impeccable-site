## Kapan menggunakannya

Jalankan `/impeccable document` setelah Anda memiliki cukup sistem visual untuk didokumentasikan: warna, tipografi, setidaknya tombol dan kartu. Perintah memindai codebase Anda, mengekstrak token dan pola komponen yang ditemukannya, dan menulis `DESIGN.md` di root proyek yang mengikuti [format DESIGN.md Google Stitch](https://stitch.withgoogle.com/docs/design-md/format/), enam bagian dalam urutan tetap, interoperabel dengan setiap alat lain yang sadar DESIGN.md.

Gunakan ketika:

- **Anda baru menjalankan `/impeccable teach`** dan `PRODUCT.md` sekarang ada. Document adalah file sisi visual yang cocok.
- **Sebuah perintah mendorong Anda ke sini.** Live, craft, dan polish semuanya membaca DESIGN.md. Jika hilang, skill menyarankan menjalankan document dulu.
- **Desain telah menyimpang** dari DESIGN.md yang lebih tua dan file tidak lagi menggambarkan sistem yang hidup.
- **Sebelum redesain besar**, untuk menangkap kondisi saat ini sebagai referensi untuk arah berikutnya.

Untuk proyek tanpa kode (proses `teach` baru, belum ada yang dibangun), ada mode seed: `/impeccable document --seed` mengajukan lima pertanyaan strategis cepat (strategi warna, arah tipografi, energi gerak, referensi, anti-referensi) dan menulis kerangka. Jalankan kembali dalam mode scan setelah ada kode.

## Cara kerjanya

Proses scan menemukan aset desain dalam urutan prioritas: CSS custom properties, konfigurasi Tailwind, tema CSS-in-JS, file token desain, sumber komponen, stylesheet global, dan akhirnya gaya yang dihitung dari output render langsung jika browser tersedia. Skill mengekstrak otomatis semua yang bisa, kemudian mengajukan satu pertanyaan terkelompok untuk bagian yang membutuhkan input kreatif: **Bintang Utara Kreatif** (metafora tunggal bernama untuk seluruh sistem, seperti "The Editorial Sanctuary"), nama warna deskriptif, filosofi elevasi, dan karakter komponen.

Output adalah DESIGN.md dengan tepat enam bagian: Ikhtisar, Warna, Tipografi, Elevasi, Komponen, Hal yang boleh dan tidak boleh dilakukan. Header tetap karakter-per-karakter sehingga file dapat diurai oleh alat lain. Di sampingnya, `DESIGN.json` ditulis sebagai sidecar yang dapat dibaca mesin. Sidecar itulah yang digunakan panel desain live-mode untuk merender tombol, input, nav, dan kartu tile *proyek ini* yang sebenarnya alih-alih aproksimasi generik.

Setiap perintah lain membaca DESIGN.md saat pemanggilan. Varian, polish, audit, dan fitur baru mewarisi sistem visual tanpa diberi tahu.

## Cobalah

```
/impeccable document
```

Pada proyek dengan token yang sudah didefinisikan, ini membutuhkan waktu sekitar dua menit: scan menemukan palet dan tumpukan tipografi Anda, Anda memilih Bintang Utara dari 2 atau 3 opsi, mengkonfirmasi nama warna deskriptif ("Deep Muted Teal-Navy", bukan "blue-800"), dan file mendarat di root proyek.

Pada proyek baru:

```
/impeccable document --seed
```

Lima pertanyaan, sekitar lima menit. File adalah kerangka, ditandai dengan komentar `<!-- SEED -->` sehingga jujur tentang apa adanya. Jalankan kembali tanpa flag setelah Anda mengimplementasikan token.

## Jebakan

- **Menjalankannya terlalu dini.** Pada proyek tanpa token yang diimplementasikan, mode seed benar. Jangan fabrikasi spesifikasi lengkap yang tidak dapat didukung oleh kode. DESIGN.md palsu lebih buruk daripada tidak ada DESIGN.md.
- **Memperlakukan DESIGN.md sebagai dokumentasi untuk manusia saja.** Ini terutama untuk AI. Setiap perintah lain membacanya. Kekuatan format ("tidak pernah", "selalu", Aturan Bernama) disengaja.
- **Menambahkan bagian Tingkat Atas Tata Letak / Gerak / Responsif.** Spesifikasi memiliki enam bagian, dalam urutan tetap, dengan nama tetap. Lipat konten tata letak atau gerak ke Ikhtisar (aturan tingkat filosofi) atau Komponen (perilaku per-komponen).
- **Menimpa DESIGN.md yang ada secara diam-diam.** Document selalu mengkonfirmasi dulu. Jika Anda ingin mulai segar, ganti nama file yang ada ke lokasi lain atau beri tahu skill secara eksplisit untuk menimpa.
