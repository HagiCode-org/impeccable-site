## Коли використовувати

`/impeccable` -- це домашня команда. Викличте її безпосередньо, коли хочете вільну дизайнерську роботу з повним завантаженим довідником, не обираючи спеціалізовану команду. Це запасний варіант, до якого ви звертаєтесь, коли жодна з 23 спеціалізованих команд (`audit`, `polish`, `critique` та інші) не відповідає точно тому, що ви намагаєтесь зробити.

Зверніться до `/impeccable` безпосередньо, коли:

- **Ви не впевнені, яка команда підходить.** Опишіть, що хочете, простою англійською, і нехай навичка обере правильний підхід.
- **Робота охоплює кілька дисциплін.** "Переробіть цю hero-секцію" зачіпає макет, шрифти, колір та рух. Одна команда не може володіти цим.
- **Ви хочете повний дизайн-інтелект без обмежень.** Усі довідкові файли завантажені, всі антипатерни перевірені, без наперед заданого процесу.

Для структурованих процесів зверніться до спеціалізованих команд у бічній панелі. Спочатку запустіть `/impeccable teach` у будь-якому новому проєкті, щоб створити PRODUCT.md та DESIGN.md. `/impeccable craft` поєднує інтерв'ю з виявленням у повну збірку з живою візуальною ітерацією. `/impeccable shape` створює дизайнерський бриф без торкання коду. `/impeccable live` надає вам браузерний пікер із трьома варіантами для кожного елемента. Команди оцінки та вдосконалення (`audit`, `critique`, `polish`, `typeset`, `layout`, `colorize` та інші) кожна володіє конкретним фрагментом роботи.

## Як це працює

Більшість UI, згенерованих AI, зазнають невдачі однаково: типові шрифти, фіолетові градієнти, сітки карток на сітках карток, скляна морфологія всюди. `/impeccable` дає вашому AI сильну точку зору. Він завантажує категоричний дизайнерський довідник плюс довгий список антипатернів, а потім спонукає модель зробити конкретний естетичний вибір до написання жодного рядка коду.

Два файли в корені вашого проєкту визначають все, що робить навичка:

- **`PRODUCT.md`** містить регістр (бренд проти продукту), цільових користувачів, особистість бренду, антиреференси, принципи дизайну. Відповідає на "хто, що, чому".
- **`DESIGN.md`** містить кольори, типографіку, висоту, компоненти, правила "робити і не робити" у шестисекційному форматі Google Stitch. Відповідає на "як це виглядає".

Кожна команда читає обидва файли перед генерацією. **Регістр** визначає, які значення за замовчуванням завантажуються. Бренд (маркетинг, лендінги, портфоліо, де дизайн Є продуктом) та продукт (UI додатків, дашборди, інструменти, де дизайн СЛУЖИТЬ продукту) мають різні значення за замовчуванням для шрифтів, руху, кольору та щільності. Вказавши це один раз у PRODUCT.md, ви гарантуєте, що `/impeccable typeset` не запропонує редакційно-журнальні шрифти для дашборду і не запропонує продуктивні значення за замовчуванням для кампанійної сторінки. Дивіться [підручник з бренду проти продукту](/tutorials/brand-vs-product), щоб дізнатися, як вони розходяться.

При першому використанні в проєкті навичка автоматично запускає процес `teach`: коротке інтерв'ю, яке записує PRODUCT.md, а потім делегує `/impeccable document` для DESIGN.md. Наступні команди читають файли без повторних запитів.

## Спробуйте

```
/impeccable redo this hero section
```

```
/impeccable build me a pricing page for a developer tool
```

Обидва промпти навмисно розпливчасті. `/impeccable` обере сильний естетичний напрямок, узгоджений із вашим регістром, зробить вибір нестандартних шрифтів, уникне AI-палітри кольорів і прийме ті види конкретних рішень, які прийняв би дизайнер. Не потрібно спочатку вибирати назву команди, не потрібно слідувати покроковому процесу.

Для візуальної ітерації в браузері замість чату:

```
/impeccable live
```

Оберіть будь-який елемент на вашому запущеному dev-сервері. Залиште коментар або позначку. Отримайте три продукційні варіанти, гаряче замінені через HMR. Прийміть той, який хочете, і він запишеться у вихідний код.

## Закріпіть команди як ярлики

v3.0 об'єднала 18 окремих навичок в єдиний `/impeccable` з 23 підкомандами. Якщо вам не вистачає короткої форми конкретної команди, закріпіть її назад:

```
/impeccable pin critique
```

Відтепер `/critique` викликає `/impeccable critique` безпосередньо. Він записує легенавичку-перенаправлення, яка делегує до батьківської, тому оновлення навички проходять без повторного закріплення.

Корисні закріплення для спроби:

- `/impeccable pin polish` для фінального проходу
- `/impeccable pin audit` для детермінованих перевірок a11y/продуктивності
- `/impeccable pin live` для процесу ітерації в браузері
- `/impeccable pin critique` для дизайнерського огляду

Для видалення: `/impeccable unpin critique`. Закріплення живуть як директорії з префіксом `i-` у вашій папці навичок харнесу (`.claude/skills/i-critique/`, `.cursor/skills/i-critique/` тощо), тому ви також можете видалити їх вручну.

## Підводні камені

- **Ставлення до цього як до style guide.** Це категоричний дизайнерський партнер, а не лінтер. Значення за замовчуванням існують, щоб підняти планку, а не перекрити ваші судження. Якщо у вас є реальна причина не погодитися (настанови бренду, обмеження доступності, дослідження користувачів), не погоджуйтесь і поясніть чому. Навичка працюватиме з вами. Що дає гірший результат -- це ігнорування думки без причини.
- **Очікування, що це виправить існуючий код.** `/impeccable` призначений для створення. Для вдосконалення зверніться до `/impeccable polish`, `/impeccable distill` або `/impeccable critique`.
- **Запуск до того, як `teach` зберіг контекст.** У новому проєкті він проводить інтерв'ю на льоту, що нормально, але повільніше. Запуск `/impeccable teach` явно як вашої першої команди -- трохи плавніше.
- **Пропуск питання про регістр.** Значення за замовчуванням для бренду та продукту розходяться настільки, що запуск з неправильним регістром дає тонко неправильний результат. Якщо в `PRODUCT.md` немає поля `## Register` (застарілий формат), запустіть `/impeccable teach`, щоб додати його.
